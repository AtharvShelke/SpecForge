Build a fully dynamic product filtering and specification system for the ecommerce platform.

First, completely remove the entire product variants system from both backend and admin panel. Remove:

Product variants
Variant management
Variant combinations
Variant-specific pricing
Variant-specific stock
Any related UI, database schema, APIs, and logic

The platform should now use a single-product structure without variants.

Next, implement a fully dynamic filtering system for products.

Filtering System Requirements

When a user opens a category page:

Show all products belonging to that category
If the category contains subcategories, display a subcategory dropdown/select
When a subcategory is selected, products should update accordingly

The filter sidebar must dynamically load filters based on:

selected category
selected subcategory

Filters must NEVER be hardcoded in frontend or backend.

All filter definitions, values, and relationships should come from the database.

Required Filters:

Category
Main category
Subcategory dropdown
Brand
Checkbox multi-select
CPU Socket Type
Checkbox multi-select
Series
Checkbox multi-select
Price
Min/max slider with two handles
Separate min and max input fields
Slider updates inputs in real time
Stock Status
Checkbox options:
In Stock
Out of Stock
User can select both

Dynamic Filter Logic

Filters must work dynamically and depend on each other.

Example:

If user selects Brand = AMD
Then all remaining filters should only show values available within AMD products

For example:

Series filter should only display AMD-related series
CPU socket types should only display socket types available for AMD products
Stock status should only display statuses available for AMD products

The same behavior should apply to every filter combination.

Filtering behavior should function similar to Amazon, Flipkart, or Newegg faceted filtering.

Product Grid Behavior

The product grid must:

Update instantly when filters change
Use AJAX / API-based fetching
Never reload the page
Show loading state/skeleton while fetching
Preserve selected filters during updates

Selected filters should appear above the product grid as removable tags/chips.

Include:

Individual remove buttons
“Clear All Filters” button

Backend Architecture

Create a database-driven filtering architecture.

Suggested structure:

Filter Groups
Brand
CPU Socket Type

etc.
Filter Values
AMD
Intel

LGA1700
Ryzen 7000
etc.
Category Filter Mapping
Determines which filters belong to which category/subcategory

The backend should dynamically return:

available filters
available filter values
min/max price range
filtered product count
filtered product data

Admin Panel Requirements

When admin creates or edits a product:

Admin first selects category/subcategory
Based on selection, dynamic specification fields should appear automatically

Example:
Motherboards category may show:

Socket Type
Chipset
RAM Support
Form Factor

CPUs category may show:

Socket Type
Core Count
Thread Count
Series

These specification fields should come from the database and be manageable by admin.

Admin must be able to:

Add new specification fields
Edit specification fields
Assign fields to categories/subcategories
Add possible filter values

Important:
Any specification field added by admin should automatically become available as a filter in the frontend filtering sidebar.

Frontend UX Requirements

Filtering experience should be modern and smooth:

Real-time updates
Debounced API calls if needed
Responsive design
Mobile-friendly filter drawer
Proper loading indicators
Empty state handling
URL query synchronization for filters
Back/forward browser support

Technical Expectations

Implement:

scalable filtering architecture
faceted filtering logic
optimized database queries
indexed filter tables
efficient API responses
reusable filter components
clean separation between filters/specifications/categories

The entire system must be extensible, dynamic, and database-driven. No filter values or filter structures should be hardcoded anywhere in the application.
